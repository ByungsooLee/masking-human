# 2台のMacで開発・モック確認を続ける

## 共通の開発タスク

両方のMacで同じChatGPTアカウントとワークスペースを使い、同じCodexクラウドタスクを開きます。タスクのURLをブックマークしてください。別のタスクを新規作成した場合は同じ作業ディスクではありません。GitHubのブランチ・PRとこの文書を引き継ぎ元にします。セッションやタスクの保持期間は契約・サービス側の仕様によるため、未コミットの変更の恒久保存先とは扱いません。

クラウドタスクは既に分離されています。既存の `/workspace/masking-human` を使い、明示的な依頼なしにGit worktreeを追加しません。

## モック専用モード

```bash
npm ci
npm run dev:demo
```

`/live?mock=1` が動作確認の入口です。この専用モードでは、`?mock=1` を外した `/live` もモックになり、マイク・カメラを取得しません。用意した会話と合成音声を使います。本人・AIの実音声や外部カメラ映像の検証にはなりません。

モック素材は冒頭の同期音と無音区間を持つ合成WAVです。従来のモック収録ではChromiumで空の録音が保存され、ZIPに音声が含まれないケースが確認されたため、実収録とは独立した固定音声データへ変更しています。会話を読み上げた音声や本人／AIの分離トラックを生成するものではありません。

`NEXT_PUBLIC_DEMO_ONLY=1` は**ビルド時にも設定**します。全APIパス・全HTTPメソッドを `src/proxy.ts` で403にし、APIキーが誤って設定されてもAPIハンドラーへ到達させません。写真許可ページの日英表示は残しますが、個人情報入力・署名・保存を無効にします。利用料取得とモックのサーバー利用記録も行いません。通常モードの既存フローは維持します。

実際の同意取得・収録には使わず、個人情報・本物の署名を入力しないでください。ホスティング先には `OPENAI_*`、`CONSENT_*`、`RESEND_API_KEY`、Supabaseの認証情報を設定しません。既存の本番プロジェクトの設定を流用しません。

productionでの確認は、開発サーバーを停止してから実施します。

```bash
OPENAI_LIVE_TEST=0 SUPABASE_INTEGRATION_TEST=0 npm test
npx next typegen
npx tsc --noEmit
npm run build:demo
npm run start:demo
```

Google Fontsをビルド時に取得するため `fonts.googleapis.com` と `fonts.gstatic.com` へのHTTPS通信が必要です。取得したフォントはアプリ側から配信されます。通信許可が反映されるまではproduction buildを検証済みと扱いません。証明書検証の無効化や偽のフォントで成功扱いにしないでください。

## ブラウザ検証

モック専用サーバーを起動した状態で実施します。既定の接続先は内部ポート3000です。

```bash
npx playwright install chromium
npm run test:demo:e2e
```

既存のChromiumを使う環境では `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:demo:e2e`。別の内部ポートを使うときは `DEMO_BASE_URL` を指定します。外部デプロイの検証には、公開を承認しアクセス制限を設定した後、同じ変数でHTTPS URLを指定します。ログインが必要なサイトにはこのコマンドだけでは入れません。保護を解除してテストを通さないでください。

自動テストでは日英の準備→同期合図→会話→発言除外→分析候補→最終分析を操作します。スマホのチャット／マップ切り替え、署名非収集、履歴のZIP・字幕・CSV・イベント・合成音声・WAVダウンロード、リロード後の履歴保持、別ブラウザで共有されないこと、写真許可画面の無効化、全API拒否を確認します。通常のサンプル会話は約3分で、自動テストではブラウザの時計を区切って進めます。実API・実メール・実署名は使いません。

## URLの違いと推奨構成

| 用途 | URLの性質 | 期間・制限 |
| --- | --- | --- |
| クラウド開発サーバー | 実行中の環境の内部サービス | このオンボーディング画面には共有HTTPSプレビューの発行機能がありません。内部ポートは別MacからアクセスできるURLではありません。プロセスは再開時に起動し直します。 |
| Vercel Preview（承認後） | コミットごとのHTTPS URL | デプロイが保持されている間の一時確認用。削除・保持ポリシー・契約に左右され、恒久URLとは扱いません。認証済みメンバーだけが入れる設定を確認します。 |
| Vercelの専用デモプロジェクト（承認後） | プロジェクトの固定HTTPSドメイン | 同じURLを次のデプロイへ更新できます。プロジェクト・アカウントを維持する期間が前提です。本番ドメインもアクセス制限の対象であることを、実際のアカウントで確認してから公開します。 |

推奨構成は**本番アプリと分けたVercelのモック専用プロジェクト1つ**です。Next.jsの標準Node.js構成、Node.js 24、ビルドコマンド `npm run build:demo`、Preview/Production両方に `NEXT_PUBLIC_DEMO_ONLY=1` を設定し、秘密情報は入れません。既存のNext.js APIを動かせる構成ですが、モックでは全APIを拒否します。実データ用の永続保存先・メールサービスは接続しません。

初回デプロイの前に、今回のPRのコミットを対象にしていることを確認します。mainへのマージ前は `feat/safe-mock-preview` を指定し、古いmainを既定コマンドのまま自動デプロイしないでください。ビルドコマンド・環境変数・アクセス制限を先に設定できない場合はデプロイを開始しません。

GitHub接続、アカウント作成・連携、外部デプロイは実行前に所有者の承認が必要です。Vercel Authentication等のDeployment Protectionを使い、2台のMacで許可済みの同じアカウントへログインして確認する方針です。Previewだけでなく固定ドメインも保護されるか、利用プランで実現できるかを接続後に確認します。固定ドメインの保護が有料であれば、課金せず作業を止めて相談します。認証なしの無制限公開に切り替えません。

API課金はこのモードでは発生しません。ただしホスティングのビルド・転送・実行枠、Codex利用枠は各サービスの契約に従います。無料枠の適用条件・商用利用可否・上限・超過時の動作はアカウントで確認し、有料プラン契約や自動課金を勝手に有効にしません。実API、メール、実同意保存を将来有効にする作業は別件です。

## データと未対応事項

同じURLでも、履歴・合成録音はMacごとのブラウザIndexedDBに保存されます。別Mac・別ブラウザ・Previewと固定URLの間では共有されません。`.env.local` と端末内の同意書もGitHub経由では移行しません。必要なデモ素材は履歴の「素材保存・SNS書き出し」から個別またはZIPで保存してください。

履歴のクラウド共有には認証、所有者ごとのアクセス制御、永続ストレージ、保持・削除・バックアップの設計が別途必要です。今回の対象外です。クラウド作業環境の一時ディスクを本番の署名・録音の保存先にしません。iPad・外付けマイク・実API音声・外部映像同期・実メールは、このモック検証では確認しません。
