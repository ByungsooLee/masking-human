# インタビュー開発ナレッジ

[English](en/README.md)

更新日：2026-10-23（日本時間）。照合基点：`e81bcb3`（main）。

コスメを入口に、その人の暮らし・記憶・選択・大切なことを本人の言葉で聞くアプリの、開発・改善の入口です。商品レビューや心理診断、感動的な物語の収集を成功条件にしません。

## 読む順序

1. [現行仕様](current-spec.md)：現在の体験、実装の所在、限界。
2. [聞き方の実践集](interview-playbook.md)：次の質問の判断、状況別対応、修正済みの創作例。
3. [品質評価](quality-evaluation.md)：観察基準、テストケース、実音声の確認手順。
4. [照合・判断記録と未決事項](decisions-and-open-questions.md)：提出資料との相違と扱い。
5. [出典台帳](sources/README.md)：原資料・実装・テストへのリンク。
6. [変更履歴](CHANGELOG.md)：更新範囲と検証記録。
7. [開発時の必読・変更手順](development-workflow.md)：実装前の確認と意図しない上書きの防止。

## 情報の区分と扱い

- **現行実装**：コードで確認できる挙動。実装されていても会話品質や運用上の妥当性の実証を意味しません。
- **現行指示**：実際にモデルに渡すプロンプト。モデルが必ず守る保証ではありません。
- **提出資料の知見**：NotebookLMの出力に含まれる内容。元ノートブックの資料そのものは未受領です。
- **提案・未決**：新たな評価基準、運用判断、実装の追加案。採用済み機能として扱いません。

このフォルダは現在の `/live` の引き継ぎに使います。古い5段階・最大8問のエンジンは残っているため、旧資料は履歴として保持します。詳細実装はリンク先コード、モデルへの指示の実体は [共通プロンプト](../../prompts/interviewer.md) と [スタイル](../../prompts/interviewers/) を確認してください。文書と実装が異なる場合は、違いを記録してから修正し、どちらかを無断で確定仕様にしません。

## 更新ルール

- 仕様変更時は、この索引・該当文書・判断記録・変更履歴を同じPRで更新します。
- 原資料は上書きせず、`sources/YYYY-MM-DD-説明.md` として追加し、出典台帳に受領日と限界を記録します。
- 例示は実録／創作を区別し、個人情報・署名・実録音・APIキーをここへ保存しません。
- 新しいシステムプロンプト全文を別管理しません。指示を変える場合は実際の `prompts/` と関連テストを変更します。
- 検証結果には日付・範囲を付け、モック確認と実音声評価を分けます。

- 日本語が編集元、`en/` が対応訳です。日英は同じPRで更新し、翻訳によって別仕様を作りません。不一致は判断記録と実装を照合して解消し、黙って片方を採用しません。直接のユーザー指示が優先します。
- 受領したNotebookLM原文は共有の原資料として保存し、翻訳・修正で上書きしません。
