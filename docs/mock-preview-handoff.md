# 安全なモック検証と複数Macからの引き継ぎ

この手順は **開発用のデモ専用** です。実際のインタビュー収録、同意取得、署名、メール送信には使用しないでください。

## GitHub / ブラウザ版Codex

1. どちらのMacでも同じGitHubアカウントでCodexのブラウザ版を開き、`ByungsooLee/masking-human` を選択する。
2. 作業開始前に最新の `main` と `AGENTS.md`、`docs/development-handoff.md` を読む。別のCodexタスクで変更がある場合は最新コミットを取り込む。
3. 機能ごとに新しいブランチ・PRを作り、CI結果を確認してからレビューする。mainへのマージはオーナーの承認後に限る。
4. ローカルの `.env.local`、ブラウザのIndexedDB、録音、同意PDFはGitHubで同期されない。別Macで履歴を表示できると想定しない。

## 課金なし検証

APIキーや同意保存設定を **一切設定しない隔離環境** で実行する。既存の `.env.local` がある端末では、意図せず読み込まれないよう別のクリーンな作業環境を用いる。

```bash
npm ci
OPENAI_LIVE_TEST=0 SUPABASE_INTEGRATION_TEST=0 VOICE_LIVE_TEST=0 npm test
npx tsc --noEmit
npm run build
NEXT_PUBLIC_LIVE_MOCK=1 npm run dev
```

ブラウザで `/live?mock=1` を開く。日本語・英語、準備→同期合図→会話→発言除外→分析候補→最終分析まで、架空の人物情報だけで動作を確認する。次に `/live/archive` から該当履歴と編集素材ZIP、SRT/CSV、マップ、replay.htmlのダウンロードを確認する。デモは実録音ではなく、分離音声が存在しない場合がある。写真同意ページ `/photo-consent` は閲覧・言語切替までとし、署名保存は試さない。

**URLを公開する前に**、該当環境で実OpenAI API、同意保存・PDF取得、メール送信が利用できないことを、サーバー側の禁止設定やルート制御とともに検証する。APIキーを削るだけでは十分な公開対策ではない。運営者認証のない履歴表示UIも個人情報入りデータに使わない。

## URLの種類と制約

- **一時プレビュー**: Codexクラウド開発環境のポートプレビュー。環境が起動している間だけ有効なことがあり、再起動や環境削除でURLが変わる。アクセス制限・外部公開範囲はプレビュープロバイダの設定に依存。
- **継続利用URL（候補: Vercel）**: GitHub接続によるプレビュー/本番デプロイ。プロジェクトURLは継続利用できるが、無料枠の制限・ビルド/通信量・アクセス制限などは契約と設定を確認する必要がある。初期状態でインターネット公開しない。デプロイ保護、認証、および実API・同意・メール処理をサーバー側で確実に無効化する変更・検証を先行させる。
- 外部サービスの接続、課金プランの契約、公開権限変更、実デプロイはオーナーの事前承認を得る。

このPRのCIはクリーンなGitHub Actions runnerで `npm ci`・非課金テスト・型チェック・production build を実行する。これだけではブラウザE2E、iPad、外付けマイク、各種ダウンロード、公開時のセキュリティを証明しない。
